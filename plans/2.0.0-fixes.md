## Batch A — `cart-panel` package code

Branch: `feat/panel-fixes`

### A1. Bare `change` on quantity input silently deletes the line

`src/cart-item.js:213-216` — the native `change` handler emits `quantityInput.value` raw, bypassing
`#commitQuantityInput()`. Empty field → `parseInt('')` → `NaN` (`cart-item.js:341`). In optimistic
mode `cart-panel.js:625-626` coerces `NaN` to `0`, then destroys the line and POSTs a removal.

Trigger: select the quantity field, hit Delete to retype, click away. The line vanishes.
Without `optimistic` it's not a delete but still broken — `JSON.stringify({quantity: NaN})` sends
`"quantity":null`.

Fix: route the branch through the path that already exists.
```js
if (quantityInput) this.#commitQuantityInput(quantityInput);
```
Gets clamping, restore-on-invalid, and skip-if-unchanged for free. Also closes the unclamped
`max="5"` → type `999` → tab out hole.

### A2. Delayed insert appends duplicate `<cart-item>` nodes

`src/cart-panel.js:1081-1089` (JS template) and `:1188-1202` (section). Both snapshot missing keys,
`setTimeout(..., 100)`, then insert unconditionally. No re-check, no cancel, no timer handle.

Trigger: double-click add-to-cart. Render 1 schedules key1 at t+100; render 2 at t≈50 still sees an
empty DOM, schedules key1 *and* key2 at t≈150. key1 lands twice. The demo reproduces it —
`demo/index.html:1667` calls `refreshCart()` per add, and `show()` already calls it at
`cart-panel.js:310`.

Fix: re-check inside the timeout at both sites, reusing the selector already at `:1107`.
```js
if (itemsContainer.querySelector(`cart-item[key="${key}"]:not([state='destroying'])`)) return;
```
Keep the 100ms — it lets the outgoing height collapse start before new nodes land. No generation
counter; the DOM is the source of truth here.

### A3. Failure rollback clobbers other in-flight lines

`src/cart-panel.js:863-871` — `#revertToServerTruth()` assigns `#currentCart = serverCart` directly.
The success path (`#reconcileWithServerCart`, `:782-784`) runs it through `#preserveInFlightLines()`
first. Line A 422s while B is still optimistic → B flashes backward and `data-changed` broadcasts a
stale subtotal until B settles.

Fix: one line.
```js
const revertedCart = _.#preserveInFlightLines(serverCart);
```
then use it in the three statements at `:868-871`. Safe by construction: key A's own entry already
has `inFlight = false` (`:756`) and `pending === null` (`:746`), so the guard at `:813` skips it —
A still reverts, other keys stay projected.

### A4. `destroyYourself()` ignores the CSS duration variable

`src/cart-item.js:653-660` reads `--cart-item-destroying-duration`, applies it to the transition,
then hard-codes `setTimeout(() => _.remove(), 600)`. A theme setting `2s` gets a jump-cut at 600ms.
`#handleTransitionEnd` (`:300-303`) already removes on `transitionend`.

Fix: derive the failsafe from the value already read, plus slack. Or delete the `setTimeout` and let
`transitionend` own removal. Prefer whichever reads cleaner in context — do not add a timer field.

Note: the JS fallback string `'400ms'` is dead — `cart-item.css:8` sets `600ms`, so the var always
resolves. Worth aligning the fallback while in there.

### A5. `#renderCartSubtotal` throws on a cart without `items`

`src/cart-panel.js:917-923` guards `!cartData` then dereferences `cartData.items.filter`.
`#renderCartCount` routes through `#getVisibleCartItems`, which guards `!cartData.items` at `:1335`.
Reachable via `show(triggerEl, cartObj)` with a caller-supplied cart.

Fix: add the missing guard. Both reviews also flagged that count/subtotal math is duplicated across
`#renderCartCount`, `#renderCartSubtotal`, and `#addCalculatedFields` — extracting a helper is
optional and only worth it if it falls out of the guard fix naturally. Don't force it.

## Batch B — `gift-with-purchase`

Branch: `feat/gwp-fixes`

### B1. Disabled path deletes every tier's gift

`src/gift-with-purchase.js:338` — `#getGiftLines(cart, false)` matches every `_gwp_item` line
regardless of variant, and POSTs `quantity: 0` for all of them. The threshold-drop path passes
`true` (`:319`). README documents multi-tier at `:356` with two sibling components.

Worse, tier B never comes back: `:262` requires `!wasActive`, and B stayed active through the
deletion.

Fix: pass `true` at `:338`. That makes `#removeAllGiftsFromCart` identical to `#removeGiftFromCart` —
delete it and call the latter from `:261`. The `false` flag then has no callers.

Blast radius: multi-tier only. Single-gift installs have one variant.

### B2. Gift only adds on the rising edge of `#isActive`

`:262` requires `#isActive && !wasActive && !#isAdded`. `connectedCallback` seeds `#isActive` from
the `current` attribute (`:43`, `:67`). A theme that populates `current` from the live cart total
boots already-active, so the add branch is unreachable forever.

README invites exactly that: `:132` describes `current` as "Current cart amount (typically set
automatically via cart-panel)" — which is false; cart-panel only sets the private field via events.
Basic Usage at `:53` shows `current="45.00"`.

Fix: drop `!wasActive` from `:262`. `!#isAdded` already prevents duplicates and is re-derived from
the server cart at `:222-223` before every cart-event-driven `#updateState`.

**Behavior note for the PR:** without the edge guard, a gift a shopper manually deleted re-adds on
the next cart event. Currently harmless — gifts carry `_hide_in_cart` (`:298`) and the panel exposes
no UI to remove them. Flag it anyway.

### B3. Setters fabricate an empty cart, so removal never fires

`:419-431` — `setCurrentAmount()` and `setThreshold()` both call `#updateState({ items: [] })`.
Removal filters an empty array, finds nothing, sets `#isAdded = false`, sends no request
(`:319-323`, and identically at `:339-342`). Asymmetric: `#addGiftToCart()` needs no cart, so a
setter can add a gift but never remove one.

### B4. Disabling via attribute doesn't remove the existing gift

`:109-113` — `attributeChangedCallback` recalculates flags and redraws but never calls
`#updateState()`, so no mutation path runs. Same in `connectedCallback` (`:53-60`). README `:302`
promises "`ended` and `disabled` both hide the component while still removing any existing gift
items"; package `CLAUDE.md:43` repeats it.

**B3 and B4 share one fix.** Let `#updateState` accept a null cart, and have the remove paths fetch
live truth instead of returning early:
```js
if (!cart?.items) cart = await (this.#cartPanel?.getCart?.() ?? fetch('/cart.js').then(r => r.json()));
```
`cart-panel` already exposes public `getCart()` (`cart-panel.js:338`). Then call `#updateState(null)`
from both setters and from the disabled branch of `attributeChangedCallback`.

Blast radius: B3 is imperative-API only and self-heals on the next `cart-panel:data-changed`. B4
hits the default install but is usually deferred, not permanent — the real gap is a page where the
attribute flips and no cart activity follows, and the hidden gift rides to checkout.

## Batch C — `cart-progress-bar` + all docs

Branch: `feat/docs-and-progress-bar`

### C1. `listen-event` detach uses the new name

`packages/cart-progress-bar/src/cart-progress-bar.js:114-118` assigns `#listenEvent` before calling
`#detachListeners()`, so `removeEventListener` unbinds under the wrong name. Old subscription leaks;
every change adds another live handler. The `listen-selector` case is fine — it detaches off the
cached `#listenTarget`.

Fix: move `_.#detachListeners();` above the assignment.

## Not doing

- **Section-ID race** (Sol #2). Mechanism confirmed at `cart-panel.js:1298-1300`, but no trigger
  exists: `section` is written once in Liquid, and the only runtime writer (`demo/index.html:1682`)
  toggles to `null`, which short-circuits. The proposed capture-before-await also wouldn't fix the
  ordering problem it was gesturing at — that needs a generation counter, unearned here.
- **Wiring `#lineRequests` into the default mutation path** (Grok Q4). The race is real, but
  `optimistic` exists precisely because the default path is the simple one, and package `CLAUDE.md`
  §8 freezes it byte-for-byte. The copy-pasted `#handleCartItemRemove` / `#handleCartItemQuantityChange`
  pair (`:529-595`) could be collapsed to one helper with zero behavior change — leave it for now
  rather than touch frozen code for a refactor nobody asked for.
- **Retiring the EventEmitter bus.** Both reviews want `on`/`off` as thin `addEventListener`
  wrappers. It's the right call eventually and it drops a dependency, but it's breaking. Docs fix
  now (C2), API decision separately.
- **Routing GWP writes through the panel.** Confirmed as a second Shopify writer, but
  `#preserveInFlightLines` (`cart-panel.js:807-830`) already re-pins locally projected quantities on
  every refresh, gift lines are hidden from the panel, and Shopify serializes cart writes per
  session. Worst observable outcome is a one-frame progress-bar wobble. Not worth a cross-package
  API change in 2.0.0. Cheap partial: `await` the refresh at `gift-with-purchase.js:305, 369` so
  `gwp:added` consumers can sequence off it.
- **Structural refactors.** Both reviews independently say: don't split `CartPanel` into files,
  don't extract a shared cart-listener base for the two siblings, don't unify the three money
  formatters. Different jobs. Agreed.

## Order

A1 → A2 → A3 first: the two real shopper-facing bugs plus a one-line correctness fix.
B1 → B2 next: single-token edits.
Everything else is contained. C is parallel to A and B — no file overlap.

No test harness exists. The A1 (empty field, tab out), A2 (double-click add), and A3 (422 while a
sibling line is in flight) sequences are the regression cases worth adding alongside the fixes.
